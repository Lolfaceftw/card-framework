  <section id="runtime-pipeline" title="Runtime Pipeline">
    <compositionRoot>The runtime composes from card_framework.cli.main using `conf/config.yaml` by default in a source checkout, falling back to `src/card_framework/config/config.yaml` only when the repo-root config is unavailable such as packaged installs. The human-edited config now uses a small `selection` plus `profiles` schema, and the runtime normalizes that into explicit `llm`, `embedding`, and `stage_llm` sections before provider instantiation.</compositionRoot>
    <compositionRoot>The installed-package `card_framework.infer(...)` API now wraps that same Hydra runtime through a subprocess boundary, requires an explicit `target_duration_seconds` argument, forces `pipeline.start_stage=stage-1`, writes run artifacts under the caller-supplied output directory, and returns a typed artifact-path bundle instead of exposing Hydra details directly.</compositionRoot>
    <compositionRoot>The public packaged-runtime contract now supports `infer(..., device="cpu")` on Windows x86_64, Linux x86_64, and macOS arm64. Packaged `device="cuda"` remains Windows/Linux x86_64 only, macOS stays CPU-only, and unsupported NeMo-derived diarization backends now warn and fall back to `single_speaker` instead of hard-failing during bootstrap. The packaged path still requires an explicit device choice, treats `vllm_url` as the first-class packaged LLM override, and resolves missing API keys or access tokens before the subprocess launch so secrets do not need to travel on the CLI argv.</compositionRoot>
    <stagePlanning>
      <rule>pipeline.start_stage controls execution mode and is validated by pipeline_plan.build_pipeline_stage_plan.</rule>
      <mode id="stage-1">Run audio stage, then summarizer/critic loop, then optional voice clone and optional stage-4 interjector.</mode>
      <mode id="stage-2">Skip audio generation and start from an existing transcript JSON, then run summarizer/critic loop and optional voice clone and interjector. With live drafting enabled, stage-2 owns per-turn stage-3 rendering while the draft is being built.</mode>
      <mode id="stage-3">Skip to voice clone using an existing summary XML and transcript metadata that already points to a speaker-sample manifest. With live drafting enabled, this path still routes through the incremental live renderer in one batch so it emits the same manifest shape as stage-2 finalization.</mode>
      <mode id="stage-4">Skip directly to the interjector using an existing summary XML plus an existing stage-3 voice-clone manifest.</mode>
    </stagePlanning>
    <runtimeFlow>
      <step>Resolve logging, project root, pipeline config, audio config, and runtime device.</step>
      <step>`card_framework.cli.main`, `card_framework.cli.setup_and_run`, and packaged `infer(...)` now emit timed operator-facing `Loading ...` / `Loaded ... in X.XX seconds.` lines around slow startup and bootstrap boundaries such as lazy runtime imports, transcript loading, speaker-sample bootstrap, calibration, provider setup, retrieval indexing, packaged runtime bootstrap, and A2A server readiness.</step>
      <step>If stage-1 is active, run audio_pipeline.AudioToScriptOrchestrator to emit transcript JSON and stage artifacts.</step>
      <step>ETA learning is persisted outside the per-run stage artifact folders: the default runtime now keeps one shared SQLite ETA history store under `artifacts/audio_stage/eta_history.sqlite3` so repeated wrapper runs can reuse learned stage timings while their `audio.work_dir` artifacts remain run-scoped.</step>
      <step>Load transcript JSON into orchestration.transcript.Transcript unless pipeline.start_stage=stage-4, which runs from summary XML plus voice-clone manifest only.</step>
      <step>Generate speaker samples after transcript availability when configured, or defer them until just before the voice-clone work begins when `audio.speaker_samples.defer_until_voice_clone=true`. In live-draft mode the deferred path is still pulled forward before the stage-2 summarizer loop starts because actual audio rendering needs the manifest immediately. When stage-2 reuses a transcript that does not already carry a valid `metadata.speaker_samples_manifest_path`, the runtime now bootstraps a fresh audio inference pass from source audio, validates that inferred transcript against the reusable transcript before accepting it, remaps bootstrap speaker IDs back onto the reusable transcript speaker labels when possible, and writes only the new speaker-sample metadata back onto the reusable transcript.</step>
      <step>When live drafting is enabled and voice cloning is active, skip calibration entirely and let the summarizer and critic consume actual rendered turn durations from the persisted live-draft sidecar. When live drafting is disabled, ensure the project-level voice-clone calibration artifact exists before duration-aware summarization or critic evaluation. The calibration path can reuse an existing speaker-sample manifest or bootstrap one from transcript or audio context, but it must be regenerated when the active manifest or calibrated speaker coverage changes.</step>
      <step>When `orchestrator.loop_memory.artifact_path` is configured, the stage orchestrator scopes summarizer loop-memory artifacts by transcript hash and duration target so repeated failed critic remedies can be surfaced on later revise passes instead of being retried verbatim.</step>
      <step>Instantiate shared or per-stage LLM providers, including the optional stage_llm.interjector override, embedding provider, transcript index, local A2A apps, and the orchestrator stack.</step>
      <step>Run the stage orchestrator, persist final summary XML to workspace-root `summary.xml`, also checkpoint the same XML under the active pipeline session when session persistence is enabled, optionally finalize or render stage-3 voice cloning, and optionally run the stage-4 interjector.</step>
      <step>`card_framework.cli.setup_and_run` now creates UUID-backed pipeline sessions in `artifacts/pipeline_sessions/sessions.sqlite3`, records stage boundaries as the runtime enters and completes stage-1 through stage-4, and resumes interrupted runs from the next incomplete stage through `--resume-session &lt;uuid&gt;` instead of trying to continue from the middle of an in-flight chunk or synth call.</step>
    </runtimeFlow>

  <section id="agents-and-prompts" title="Agents And Prompts">
    <executors>
      <executor name="SummarizerExecutor">Tool-loop summarizer that mutates a message registry, supports revise mode, loop-context carryover, optional discovery guardrails, and retrieval-backed query tools. The summarizer is duration-first: turns can carry direct `emotion_vector` control, the tool loop auto-runs `estimate_duration`, and convergence is measured in seconds rather than target word count. Newly emitted summary XML is vector-first and serializes readable `emotion_categories` derived from the stored vector instead of emitting `emo_preset`. Once a mutation lands in budget, the loop auto-saves the draft, injects a bounded review-only follow-up, and falls back to submitting the current draft if the model answers that review turn with plain text instead of another tool call. In live-draft mode, add/edit/remove mutations synthesize or delete turn audio immediately through `audio_pipeline/live_draft_voice_clone.py`.</executor>

The critic now opts into a shared no-tool reasoning-loop guard, plus a critic-only stream-time repetition callback that can abort a looping streamed response, inject one corrective retry instruction, and only then fall back to the deterministic verdict path with a `CRITIC LOOP GUARD:` marker if repetition continues.</executor>

  <section id="audio-pipeline" title="Audio Pipeline">
    <responsibility>The audio subsystem converts source audio into a structured transcript and optional cloned-audio output while keeping heavy model integrations behind protocol-style adapters.</responsibility>
    <stageOneFlow>
      <step>Source separation defaults to Demucs `htdemucs`. Long recordings are split into `600s` base windows with `5s` context on each side, each window is separated independently, and the trimmed vocals windows are concatenated back into one final vocals stem so peak RAM is bounded by one window.</step>
      <step>ASR now defaults to `ibm-granite/granite-4.0-1b-speech`, preprocesses audio to mono `16 kHz`, chunks it into `25s` windows with `1s` overlap, caps generation at `96` new tokens with a stronger `1.25` repetition penalty, emits per-chunk `segment i/N` progress notes, and uses CTC forced alignment for authoritative word timestamps when enabled.</step>

      <note>Use uv run for repo commands so execution stays inside the locked environment.</note>
      <note>The preferred repo-local runtime path is the Docker operator flow centered on `card_framework.cli.setup_and_run`. `compose.yml` bind-mounts the repo checkout, loads `.env`, reuses `conf/config.yaml`, isolates both repo `.venv` directories into Docker named volumes so container runs do not leave Linux virtual environments in the host checkout, and caps runtime containers at about 8 GB RAM plus 2 GB swap through `mem_limit: 8g` and `memswap_limit: 10g`.</note>
      <note>When Docker can expose CUDA or NVIDIA devices, prefer the Compose GPU profile service `setup-and-run-gpu` over the CPU service. For Windows hosts that need NeMo-backed diarization, that GPU-profile path is a Linux container fallback on a Windows host, not native Windows NeMo support. The sampled-segment speaker bootstrap helpers now auto-delegate their diarization-only NeMo work to that Compose runtime when the local host cannot satisfy the configured backend.</note>
      <note>When validating a real run, inspect persisted logs such as `agent_interactions.log` or benchmark child logs under `artifacts/`, sample container RAM with `docker stats`, and on CUDA-capable hosts sample VRAM or utilization with `nvidia-smi` instead of inferring success from terminal output alone.</note>

It accepts `(audio_wav, output_dir, target_duration_seconds, *, device, vllm_url=None, vllm_api_key=None)`, treats the duration target and the packaged device choice as required per call, reads an optional full-config override from `CARD_FRAMEWORK_CONFIG`, and uses `CARD_FRAMEWORK_HOME` for writable runtime assets when set.</note>
